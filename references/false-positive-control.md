# 误报控制与规则校例

本文件只借鉴 LanguageTool 中与编校判断直接相关的规则设计和测试方法，不涉及软件部署或工具调用。其规则思路强调描述“错误长什么样”，而不是把所有不常见形式都当成错。因此检查规则用于发现候选问题；是否成立仍要回到上下文、体例和语义中判断。

## 正反例护栏

判断稿件时，应把下面两类例子一起考虑。若一个形式在合理语境或指定体例下成立，不得仅凭表面模式标为明确差错。

| 检查点 | 应报告的候选错误 | 不应直接判错的反例/处理 |
|---|---|---|
| 拼写 | `becuase` → `because`：明确错拼 | `colour` / `color`：分别是合法拼法；同一英式稿件混用时列体例/一致性，不把单项判成错拼 |
| 助动词与动词形式 | `She doesn't likes apples.` → 助动词后动词形式错误 | `She doesn't like apples.` → 正确形式，不应因 `like` 没有词尾变化而报错 |
| 主谓一致 | `She go to school.` → 在一般现在时普通陈述句中主谓不一致 | `The team are celebrating.` → 英式英语中可按成员整体理解使用复数，结合语境判断，不机械改为单数 |
| 句子片段 | 将 `Because it was raining.` 当作完整独立陈述，且上下文无主句/对话回应功能 → 候选残句 | 对问题 `Why did you stay home?` 回答 `Because it was raining.` → 对话中可以成立；必须看上下文 |
| 词义/答案唯一性 | 空格题没有语境，但将 `little` 与 `a little` 设计为唯一答案 → 题目可能不唯一 | `I have little water` 和 `I have a little water` 均可成句，语义不同；不能把其中一个词组本身判为语法错 |
| 引号与标点 | 标点导致句法边界错误、问句误作陈述或括号未闭合 → 报具体影响 | 英式与美式引号内标点位置可能有体例差异；无明确规定时查全稿一致性，不凭单例判硬错 |
| OCR/形近字符 | `O` 与 `0` 混淆且改变选项/数值 → 回看页面图像 | OCR 文本显示错误但原图正确 → 这是识别噪声，不是稿件错字；原图无法辨认则标材料不足 |
| 题目横线/下划线 | 只有在横线遮挡文字、长度/位置造成题意或作答异常时才报告 | 选择题 A/B/C/D 之间的排版横线、填空题留出的下划线、括号后的答题线、题号后的空白线都是作答区域，不是英文标点空格或缺字；不得把它们与逗号/分号拼接成错误 |
| 选项与填空区 | 选项字母、选项文字顺序与题干不对应，或答题线覆盖/截断选项 → 报题目/版面问题 | `A. ... B. ... C. ... D. ...` 是选择题选项；括号、下划线和长横线表示待填位置。不能把选项之间的空白、下划线或括号内空白报告为语法、标点或空格错误 |
| 事实核查 | 明确事实主张与可追溯的权威原始来源冲突 → 附来源和查询日期报告 | 事实依赖时间、上下文、定义或地域时，不用模型记忆直接判错；需核对对应来源或列编辑确认 |
| 公共服务标识译文 | 标识原文“请勿入内”，译文 `Please enter.` → 否定意义反转，作为明确的翻译差错候选；需记录标识场景及图文位置 | 普通叙述 `The notice said, “Please enter.”` 的句子语法不由公共标识标准判定；先判断文本功能，再按[公共服务英文译写索引](public-service-english-index.md)查适用分册。OCR 词条须回看原页，不确定的标牌场景/译法列编辑确认 |

## 可复用的回归测试方法

借鉴 LanguageTool 的 “should warn / should not warn” 测试方式：

1. 对每种常见问题保留一个“应报告”样例和至少一个相似但正确的“不得误报”样例。
2. 新增或修改规则/判断提示后，两类样例都要重查；若某个合法表达被误报，收紧判定条件或增加语境例外，不以扩大规则覆盖为唯一目标。
3. 用不同体裁的英语材料抽查误报，例如对话、叙事、说明文、题干和答案解析；不能只用单一语法例句校准。
4. 用户/编辑确认的案例可在获准后转成匿名化正反例，注明适用体例和判定理由；不得把一次个案直接推广成全局规则。

## 弱模型上线前验收

不要只看报告是否流畅。用一组模型未见过的已校稿材料做盲测，材料应同时包含明确错例、合法变体、答案/解析问题、定位信息和材料缺失情形。编辑预先标注标准答案，按以下项目逐项核对：

- **漏报**：已确认的差错是否被发现。
- **误报**：合法表达是否被错误判定为明确差错。
- **定位**：页码、题号和原文引句是否准确。
- **核对质量**：题目是否独立作答，答案与解析是否按材料核验。
- **流程真实性**：三校覆盖记录是否与实际提供的批次一致，未读内容是否被误报为已完成。
- **交付一致性**：问题类别、状态、计数和必需字段是否符合输出格式。

先修复高频漏报、误报和定位错误，再将编辑确认的匿名案例加入正反例库。模型能否通过验收应由这组盲测结果决定，不能由提示词长度或自我声明决定。

## 多模态模型验收记录

每次验收须记录模型名称/版本、日期、输入类型（DOCX/PDF/单页图片/扫描件）、是否提供页面图像、使用的批次大小和提示词版本。样本至少覆盖可搜索 PDF、扫描页、图片中小字号文字、双栏/表格、页码与题号错位、跨页材料及低清/倾斜页。不要把图像 OCR 成纯文本后再把该结果当作视觉核验。

对每个模型分别统计：

- **已确认差错召回率**：标准答案中的确认差错被发现的比例，并按拼写、语法、题目答案、解析推理、数字符号等类别分别看。
- **误报率/精确率**：报告候选中经编辑认定不成立的比例；合法英美变体和语境成立表达单列。
- **定位准确率**：文件页、印刷页、题号和原文引句全部正确的比例。
- **答案解析正确率**：独立解题、答案表比对和解析推导三项分别核验。
- **图像识读准确率**：原图中的字符、选项标记、表格/图示关系是否被准确读取；OCR 与原图冲突时是否标待核。
- **流程与报告一致性**：已完成页是否与三轮覆盖记录相符；问题性质、统计数量和 DOCX 交付是否正确。

先用编辑确认过的案例建立基线，不预设通用通过阈值。样本用于模型调教和验收时应分成调试集与保留盲测集；盲测集不要放进公开 Skill 参考资料或提示词，以免模型记答案而非学会检查。
