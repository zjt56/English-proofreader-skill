# 编校流程细节

入口四步见SKILL.md；这里只补读取、分组、题答和续审方法。按遇到的问题查对应节。

## 读取与定位

| 输入/试读结果 | 采用的方法 | 保留的定位 |
|---|---|---|
| DOCX | 只读提取段落/表格；自动编号、文本框、页眉页脚另核。要页码时用预览或临时PDF | 文件＋块/题号；实际预览后才记页码 |
| 旧DOC | 只读预览或临时转换副本；无转换能力则说明受限范围 | 实际预览页/题号，不当ZIP读取 |
| 可靠文字PDF | 按页读文字；字符争议、复杂表格/音标回看原页 | 原文件页，可附印刷页 |
| 扫描、乱码、错栏或混合PDF | 异常页改看清晰原图；必要时裁切/放大，混合文件逐页选方法 | 原文件页＋可见题号/词条 |
| 图片 | 按已知页序看原图；模糊时用放大/旋转副本 | 文件名＋可见页码，不猜排序 |
| 纯文本/Markdown | 按标题、段落、题号读 | 段落/短引，明示无页码 |

通常试读1–3个不同结构片段即可选方法，后遇新结构再核。坏文字层不反复全书抽取；可靠文字不先强制全书渲染。可用脚本 `prepare_review.py --pages 1,3-5 --no-render` 整理小样；复杂页再渲染。页图不清或宿主不能看图时，不能声称完成视觉核验。分栏和字体细节见 [版面规则](layout-aware-proofreading.md)。

## 结构与重点

内部只保留 `文件/版本｜范围｜结构｜关联材料｜重点/待核` 的短记录。以下项目按实际内容选择：

| 内容 | 重点 |
|---|---|
| 目录 | 标题、层级、顺序、起始页与正文逐项对应 |
| 索引 | 词头、排序、页码、重复/漏收；先确认收录口径 |
| 词表/附表 | 词头—音标—词性—义项—例句/词形；表格逐行对应 |
| 题号/选项 | 按Day/节和层级查连续性、标签、缺项、串题及编号后符号 |
| 阅读/完形/填空/变式 | 文章与题目、空号、提示词、条件和答案解析相互对应 |
| 写作 | 任务、图表、词数、人称、时态及所给范文是否一致 |
| 中文伴随文字 | 错漏、语句、标点及否定/数量/术语与英文对应 |
| 普通文章/讲解 | 拼写语法、搭配指代、逻辑、标点及规则—例句对应 |

同页可跨天/节，组内序号可跨页；不能按页判重号，也不能见重号就自动新建组。多文件先核版次和页码基准。结构脚本见 [工具说明](mechanical-checks.md)，结构通过仍须完整语言审校。

## 题目与答案

1. 读完整题干、选项和必要文章/图表，明确已给条件。
2. 先独立求解，逐项测试答案唯一性或多选要求；不先用答案表找理由。
3. 回核答案题号、词形及重复出现处，再逐句核解析的规则、引文、推理和结论。
4. 缺必要材料时限定结论。干扰项、挖空和改错材料按命题功能判断，不替学生补写答案。

## 单份稿件与三遍检查

一个版本或一套同版组件默认 `single_delivery`：结构批查后，完成三遍全文阅读，再交当前版本报告。

| 遍次 | 重点 | 注意 |
|---|---|---|
| 初检 | 基础文字、标点、语法、结构 | 候选留短引和位置 |
| 独立复读 | 语义、词性义项、题答解析 | 先不看旧台账；再合并新发现 |
| 冷读与复核 | 全稿一致性、遗漏、跨页关系 | 先完整冷读，再逐条反证候选 |

每遍覆盖同一范围的全部适用项；不能分成只查文字、只查答案、只查格式三段。正式木牍校次另按 [公司流程](mudu-three-review-three-proof.md)及实际版本推进；没有旧稿/核红稿不妨碍单版本报告。

## 长稿与续审

- 词表按Day、索引字母段、完整附表分批；练习按完整题组/文章。批量取决于可读量和模型能力，1–2页只是难读图像的试读起点。
- 保存来源/版本、已读范围和遍数、待核点、累计问题编号。上下文中断后从真实状态续接，不重复准备全书素材。
- 跨批次保留 `项目｜不同写法及位置｜确定体例｜允许例外` 的短表。术语、英美拼写、题号后符号和词性缩写全稿回查；引文、专名、不同义项不机械统一。
- 交付前扫一遍文字、标点、语法、内部知识关系、格式和图表六面，查漏而非新增六轮。外部事实检查仍服从用户范围。
- 当前检查结束即交结果，未完成范围一句话说明。内部状态及JSON字段见 [报告契约](report-schema.md)，不把工作记录堆给编辑。
