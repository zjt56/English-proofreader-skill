# Word报告交付

触发条件见 [输出规范](output-format.md)。报告内容保持“校对结果、问题条目、简短说明”，不附全套内部工作记录。

1. 按 [JSON契约](report-schema.md)形成实际结果，运行 `validate_review.py`。
2. 运行 `build_report_docx.py report.json report.docx`，脚本自动检查3000字符/10处阈值；用户要求Word时加 `--always`，指定其他字数用 `--threshold`。无Python时使用宿主Word能力，不能假称生成成功。
3. 新建“稿件名_编校问题清单_日期.docx”，存用户指定目录；未指定则存稿件目录，不能写时用可访问输出目录。重名换文件名，不覆盖原稿或旧报告。
4. 验证DOCX的ZIP/XML可读；有Word、LibreOffice或宿主渲染能力时，检查分页、截断和中英文显示。没有视觉渲染能力则如实注明，不把结构有效等同显示正常。
5. 回复简短结果和可点击文件链接，不再粘贴整份长报告。无法生成文件时说明原因，分段交完整问题清单。

生成器只呈现已写好的建议，不推测改法。QA页图仅供内部检查。
