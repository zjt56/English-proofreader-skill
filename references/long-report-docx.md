# 长报告 Word 输出

## 触发条件

- 生成最终报告 JSON 后，始终调用报告脚本；由脚本对正文按可见非空白字符计数，超过约 3,000 字符（含标点；不计未复制进报告的原稿内容）时自动生成 Word 文档，不必再次询问。不要只凭模型目测字数决定是否运行脚本。
- 用户明确要求 Word、确认位置超过 10 处或要求始终生成文件时，用 `--always`；用户指定其他阈值时用 `--threshold`。
- 若报告明显可能超过聊天输出限制，即使尚未达到默认字数，也优先生成 Word。
- 只有三校和问题台账复核完成后，才能生成“最终报告”。阶段结果须标明“阶段结果，非全稿终审”，不得包装成最终报告。

## 文档内容

完整保留 [输出格式规范](output-format.md)中的三部分和全部问题条目：

1. 标题“英语教辅编校问题清单”，附稿件名/版本、核查范围和报告日期。
2. 报告摘要：结果统计、覆盖范围、三校状态、高影响问题和限制。
3. 问题条目：按页码/题号排序，保留唯一编号、性质、影响、置信度、错误类型、原文证据、逐位置建议改法、说明依据、来源和建议处理。同页同类重复问题可压缩为位置表，但不能丢失位置或改法。
4. 覆盖与限制：逐批列出一校/二校/三校完成状态，以及缺页、缺件、OCR待核和未查范围。

外部来源使用可读的来源名称、链接和查询日期。建议处理仍是给编辑的意见，不表示已修改稿件；Word 报告是新文件，绝不覆盖或改动原稿。

## 生成和检查

- 优先使用 `scripts/build_report_docx.py` 从结构化报告 JSON 生成 `.docx`，该脚本只依赖 Python 标准库，并在生成前自行计数；默认不超过 3,000 字符时跳过，超过时自动生成。若脚本不可用，再用当前环境的 Word 文档能力判断和生成；不得假称文件已生成。
- 文件名使用“稿件名_编校问题清单_日期.docx”；清理文件名中的非法字符。若同名文件已存在，改用不冲突的新文件名，禁止覆盖。
- 将文件保存到用户指定目录；未指定时，保存到稿件所在目录。无法写入时，保存到当前工作区可访问的输出目录，并说明实际位置。
- 生成后先验证 DOCX 压缩包和 XML 可读。若环境提供 Word/LibreOffice 渲染能力，再渲染为逐页图像检查截断、分页和中英文显示；没有渲染能力时明确写“未做视觉版式复核”，不得声称已检查分页或显示效果。QA 图像仅作内部检查，不作为交付物。
- 聊天回复只给简短摘要、报告统计和 Word 文件链接，不重复粘贴整份长报告。若环境无法生成 DOCX，明确说明原因，并在聊天中分段输出完整报告作为回退。
