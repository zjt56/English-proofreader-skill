# 输出规范

报告只用三部分：**校对结果 → 问题条目 → 简短说明**。样式见 [虚构示例](../examples/editor-report-example.md)。

## 校对结果

注明稿件、实际检查范围及页码依据；分别统计明确差错、体例/一致性、编辑确认、材料不足。后两类不能算已确认差错。已完成的结构检查可简列真实条数和不符数，无数据不编写“全书通过”。

## 问题条目

按文件、页码和题号排序，唯一编号E001起。使用表格或纵向短条目，保留：

`编号｜文件页码（可附印刷页）｜题号/词条｜错误类型/性质｜原文｜具体问题及理由｜修改建议`

- 原文精确且保留必要上下文；每个位置给最小改法。不只写“有问题”“建议修改”，不重复长篇语法讲解。
- 无题号用条目/行列，无页码明示并用段落定位；多文件标清文件，不混淆文件页和印刷页。
- 多种改法均成立时说明条件并请编辑确认；高影响问题和待确认项清楚标记。置信度、逐遍记录等留在内部。
- 同性质且同改法可合并；列位置，或对全稿范围问题给范围、实际次数、计数依据和定位样例。合并项数、出现次数、出版计分分开，默认不折算差错率。
- 同一错点不要同时列成语言问题和格式问题。工具标红、字符命中及原稿正常的抽取噪声不得直接计错。
- 一般语言问题说明适用规则即可；依赖具体规范/外部核验的结论给可追溯依据，不编引文。

## 简短说明

单份稿件确已完成时写“已完成本次单份稿件的检查与复核”。正式校次按实际进度表述；只读同一版本三遍不能称三校。缺页、必要组件缺失或不可读时一句话列明实质未核范围，不列正常缺送排/核红的流程限制。

无问题写“在所列范围及可读材料内未发现问题”。不承诺全文无误，不声称已经改稿。

## 文件交付

用户要求Word、正文超过3000个可见非空白字符，或确认位置超过10处时，生成真实 `.docx`，聊天给摘要和文件链接。方法见 [Word输出](long-report-docx.md)。只在使用报告脚本时读 [JSON契约](report-schema.md)；这些字段不要求逐一展示给编辑。
